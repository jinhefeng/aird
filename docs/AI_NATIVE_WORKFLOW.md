# AI 原生研发范式：基于 DDD 与 TDD 的协作流程 (Aird 核心方法论)

本范式定义了在 AI 驱动下，团队如何利用 DDD (领域驱动设计) 构建核心逻辑，并结合 TDD (测试驱动开发) 确保质量，从而实现从需求到代码的高速闭环。

## 1. 研发流程全景图

| 阶段 | 核心活动 | AI 切入点 | 核心输出物 (AI 读写) |
| :--- | :--- | :--- | :--- |
| **1. 领域发现 (Strategic DDD)** | 业务专家与 AI 协作进行事件风暴，定义领域边界。 | 语义提取、冲突识别、上下文映射建议。 | **Context Map** (领域上下文图谱), **Ubiquitous Language** (通用语言表) |
| **2. 战术建模 (Tactical DDD)** | 定义实体、值对象、聚合根及领域服务。 | 根据业务描述自动推导聚合关系及生命周期。 | **Domain Model Schema** (领域模型定义), **State Machine** (状态机描述) |
| **3. 契约定义 (Contract First)** | 定义外部接口 (API) 与 内部消息契约。 | 根据领域模型生成符合规范的 OpenAPI/GraphQL 定义。 | **API Spec** (契约文档), **Integration Events** (集成事件定义) |
| **4. 测试规格 (TDD - Red Phase)** | 编写验收测试用例 (BDD) 与 单元测试规格。 | 基于 PRD 和契约，生成 BDD (Gherkin) 和 Mock 数据。 | **Living Test Specs** (可执行测试规格), **Acceptance Criteria** |
| **5. 自动化实现 (Green Phase)** | 编写业务逻辑代码。 | 作为 Copilot/Agent，根据领域模型和测试用例填充实现。 | **Source Code**, **Refactoring Suggestions** |
| **6. 闭环验证 (Feedback Loop)** | 运行测试并进行文档/代码同步更新。 | 分析测试失败原因，识别代码与文档的不一致。 | **Verification Report**, **Auto-Sync PRs** |

## 2. 核心协作节点深度分析

### A. 领域建模节点 (The Brain)
- **痛点**：传统 DDD 落地难，领域模型容易与代码脱节。
- **AI 切入**：AI 不仅是生成代码，它首先是**领域理解者**。它分析业务语境，确保“通用语言”在文档、接口定义、代码变量名中完全一致。
- **输出**：一个结构化的领域模型描述文件（例如 `domain.yml`），它是 Aird 平台后续所有环节的 Source of Truth。

### B. 测试规格节点 (The Guard)
- **痛点**：TDD 虽好，但写测试占用了大量开发时间。
- **AI 切入**：在代码编写前，AI 基于领域模型和业务规则生成**可执行的规格**。
- **输出**：BDD 描述（Feature files）和单元测试脚手架。这些测试在 AI 还没写一行实现代码前，就已经是“红灯”状态。

### C. 契约协同节点 (The Bridge)
- **痛点**：前后端/上下游联调成本极高。
- **AI 切入**：一旦领域模型更新，AI 自动更新契约，并生成模拟服务器 (Mock Server)。
- **输出**：可立即联调的 API Mock。

## 3. 上下游协作模式 (基于 Aird 平台)

1. **产品与业务 (PO)**：不再写冗长的 Word，而是通过 Aird 的 AI 助手，以“用户故事+业务规则”的形式输入。AI 辅助其细化边缘场景（Edge Cases）。
2. **架构与开发 (Dev)**：Aird 将业务输入转化为 DDD 模型。开发者的主要工作从“写 CRUD”转变为“**审阅并修正领域模型**”和“**处理复杂的算法逻辑**”。
3. **测试与 QA**：测试用例在需求阶段就由 AI 生成并关联到 DDD 模型。QA 的职责是“**定义质量红线**”和“**验证 AI 生成的测试用例是否覆盖了业务风险**”。
4. **协作纽带**：Aird 平台上的文档是**双向绑定**的。如果开发在 IDE 中修改了代码，AI 会检测到其与领域模型的不一致，并询问是否更新文档（Aird 平台上的文档）或回滚代码。

## 4. 为什么需要 Aird？

现有的工具（Notion、Jira、VS Code）是隔离的，知识在传递过程中会大量丢失。Aird 作为一个“下一代协作平台”，其核心使命是：**维护一个关于产品的“活的知识图谱” (Living Knowledge Graph)**。

- **它是文档库**：面向人类阅读。
- **它是数据库**：面向 AI 解析。
- **它是控制器**：驱动代码生成与测试执行。
